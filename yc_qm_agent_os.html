QM (Quartermaster) 解决了 AI 智能体进入企业生产环境的“最后一公里”痛点。 通过身份隔离（Scoped Isolation）、独立安全沙箱（Per-Scope Sandbox）与三级管控策略（Security Postures），支持多人在 Slack 和 Web 上安全并发协作。

👥

多用户与作用域隔离

区分 Personal 与 Shared Scope，隔离存储、凭证 Keychain、Memory 与 Cron 自动化。

📦

Per-Scope 持久沙箱

代码与 Shell 命令执行完全运行在独立的 Docker / MicroVM 中，工具安装状态长久保留。

🔄

多 Harness 模型解耦

不锁定 AI 厂商。支持 Claude Code、OpenCode、Codex、Pi 等多种 Agent 循环统一挂载。

🛡️

硬性命令安全拦截

预置 Command Policy，即使处于 Dangerous 模式，依然严禁递归删除与破坏性 SQL。

SYSTEM ARCHITECTURE

Headless Core 与插件化解耦

QM 采用分层结构，核心 Core 采用 TypeScript (Fastify) 开发，仅负责逻辑分发、策略鉴权与 Agent Loop 控制。 持久化层基于 Postgres（保存 Session、Memory 与队列），而所有危险操作下沉至独立的 Sandbox。

⚙️

Headless Core

无状态/通用的核心引擎，负责身份校验、策略拦截、任务队列调度与多引擎 Loop 协调。

SECURITY & AUDIT

三级安全防护模式 (Security Postures)

企业可针对不同 Scope 自由选择管控粒度。无论选择何种模式，硬性 Command Policy 黑名单均持续生效。

Strict 模式 最高安全

除了无副作用的对话回复外，所有工具调用（Shell、文件写入、网络请求）均需人工显式批准。

适用于：高权限生产账号、财务与数据库敏感操作。

Default
Auto 模式 推荐机制

内置外部内容分类器（Classifier）实时筛查风险，对于高风险命令触发阻断或推送到审批队列。

适用于：日常开发运维、自动化流程与团队协作。

Dangerous 模式 高危调试

关闭工具调用人工暂停与筛查，获得连贯快速的执行体验。但依然受底层 Command Policy 保护。

适用于：完全隔离的本地沙箱与自动化测试。

1

环境准备

Node.js ≥ 24（本实例用 fnm 24.19.0，支持原生 TypeScript 与 --env-file-if-exists）；Docker 运行时（本机为 OrbStack，承载 Postgres 与沙箱）；模型代理走 DeepSeek Anthropic 兼容端点（ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic），有效密钥取自 ANTHROPIC_AUTH_TOKEN。

2

配置 .env（安全密钥 + 模型 + 数据库）

根 .env 关键项；五个安全密钥用 openssl rand -hex 32 生成。各插件 plugins/{web-ui,auth,portal,admin}/.env 分别填入对应密钥与 OIDC 配置（Auth broker 作为 IdP，Portal 反向代理）。

HARNESS=pi
HARNESS_SECURITY_POSTURE=auto
MODEL_PROVIDER=anthropic
PI_MODEL=deepseek-v4-flash
SESSION_STORE=postgres
DATABASE_URL=postgres://postgres@127.0.0.1:5432/qm
ADMIN_GRANTS=2820317139@qq.com:org_admin
CORE_SIGNING_SECRET=…  CAPABILITY_SECRET=…
PORTAL_IDENTITY_SECRET=…  CONNECTOR_SECRET_KEY=…
SKILL_SIGNING_SECRET=…
3

启动基础设施：Postgres + mock SMTP

# Postgres（trust 认证，命名卷持久化，随 Docker 自启）
docker run -d --name qm-auth-postgres \
  -e POSTGRES_DB=qm -e POSTGRES_HOST_AUTH_METHOD=trust \
  -p 5432:5432 --restart unless-stopped \
  -v qm-auth-postgres-data:/var/lib/postgresql/data postgres:16-alpine

# mock SMTP（监听 127.0.0.1:2525，验证邮件写入 local/mock-smtp.log）
node local/mock-smtp.mjs
4

启动五个服务（Node 24）

NODE=/…/fnm/node-versions/v24.19.0/installation/bin/node
$NODE --env-file-if-exists=.env src/index.ts                    # Core       :8080
$NODE --env-file-if-exists=plugins/auth/.env plugins/auth/src/index.ts         # Auth       :8099
$NODE --env-file-if-exists=plugins/portal/.env plugins/portal/src/index.ts     # Portal     :8097
$NODE --env-file-if-exists=plugins/web-ui/.env plugins/web-ui/server/index.ts  # Web UI     :8096
$NODE --env-file-if-exists=plugins/admin/.env plugins/admin/src/index.ts       # Admin      :8090
5

邮箱登录（mock 发信，无需真实邮箱服务）

浏览器打开 http://localhost:8097 → 输入邮箱（如 2820317139@qq.com）→ 提示“检查邮箱”后，从 local/mock-smtp.log 取出一次性验证链接 http://localhost:8097/idp/verify#token=… 打开即完成登录。该邮箱已在 ADMIN_GRANTS 中，自动成为 org_admin。

grep -o 'verify#token=[^ ]*' local/mock-smtp.log | tail -1
6

模型接入：DeepSeek V4 Flash

① 模型注册表 src/model/pi-models.ts 新增 deepseek-v4-flash 条目（克隆 Anthropic 模板，128K 上下文）；② resolveModel 检测到 ANTHROPIC_BASE_URL 时覆盖 Anthropic 系模型的 baseUrl，请求统一走 https://api.deepseek.com/anthropic（该端点会把 claude 模型名自动映射为对应 deepseek 模型）；③ 对话界面模型选择器在 plugins/web-ui/src/model-options.ts 与 pi-models.ts 登记后即可选择，改完重新 vite build。

7

沙箱镜像构建

产物 qm-sandbox-local:latest（内置 node 24 / claude-code / codex / gh / aws cli）。磁盘不足时清理 ~/Library/Caches 应用缓存；GitHub 资产限速时改用 ghfast.top 前缀的临时构建文件（不修改仓库核心）。

bash scripts/local-sandbox-build.sh
docker run --rm --platform linux/amd64 qm-sandbox-local:latest sh -c 'node -v; claude --version; codex --version'
8

管理员操作（Admin 治理面板）

经 Portal 访问 /admin：用户列表、org_admin 授予 / 撤销、审计日志、指标与保留分析。所有权限以 Core 的 admin_grants 为唯一来源、按请求实时校验（GET /admin/api/whoami 返回 isAdmin / role / scopeId）。
